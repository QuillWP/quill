# Quill fuzz targets

These developer-only libFuzzer targets exercise Quill's untrusted-input
boundaries without becoming part of the application or its packages.

Install the minimal nightly toolchain and `cargo-fuzz`, then run a target from
the repository root, for example:

```sh
cargo +nightly fuzz run docx
```

The targets cover ZIP containers, XML, DOCX, ODT, RTF, HTML, native .qwp files,
image identification and decoding, settings, glossary files, print-merge data and
Markdown, plus `editing`, `character_styles` and `clipboard`, described below.

## Overnight campaign

Combined-feature Word fixtures live in the ignored `fuzz/word-fixtures/` directory.
`python3 tools/make_combination_seeds.py` prepares three RTF sources combining
nested tables, cell pictures, footnotes, sections, fields and review markup.
Open these sources in Microsoft Word and save DOCX copies under the corresponding
`word/` folder. The sources are generated inputs; the DOCX files are Word's output.
Retain native Word edits, round-trip copies and comparison evidence alongside them.

After checking the Word files, run
`python3 tools/make_combination_seeds.py --seed-corpus` to copy the DOCX fixtures
into the DOCX and ZIP corpora and the RTF sources into the RTF corpus. Seed names
use content hashes; Word lock files and macOS metadata files are excluded.
This prepares inputs only and does not launch a fuzz campaign.

Run `python3 tools/overnight_fuzz.py` from the repository root under
`caffeinate -i` to seed the missing corpora, build all fifteen targets with
AddressSanitizer and checked arithmetic, and run each for three hours.
Three targets run concurrently with three workers apiece. `--hours 8` instead
shares eight hours, giving three quarters to the targets that read whole
documents. Original sample documents are only read.

Character-style sources are made by `python3 tools/make_character_style_seeds.py`.
Save them through Word into `fuzz/word-fixtures/2026-11-01/word`, then run
`cargo run -p quill-formats --example seed_exports fuzz/word-fixtures/2026-11-01`
for Quill's own .qwp, .rtf, .htm, .docx and .odt, and the script again with
`--seed-corpus`.

`python3 tools/make_feature_seeds.py` prepares the seeds for the features added
since: border and shading colors, cropped and adjacent pictures, bullets, line
numbers, links, character styles in every story and paragraph styles linked to
them. Quill builds those documents itself, Word and LibreOffice save copies,
Quill saves those again, and everything goes into the corpora. Its docstring
lists the steps.

Each campaign has an ignored `fuzz/runs/<timestamp>/` directory containing
`report.md` (updated every thirty seconds and finalized on completion),
`status.json`, build and per-target logs, exact commands, source snapshot,
and saved failure inputs. `fuzz/runs/latest.txt` identifies the latest run.
The report distinguishes incomplete runs from completed targets; saved failures
still need reproduction and minimization before they are treated as confirmed bugs.

## Save integrity and editing properties

The DOCX and RTF targets now require every Quill export to reopen successfully.
Their native saves are compared semantically with the imported document: text,
formatting, stories, sections, comments and revision records must survive.
Exchange formats intentionally cannot preserve every imported feature, so full
semantic comparison of DOCX/RTF uses the supported documents generated by the
`editing` target instead of imposing false lossless guarantees on arbitrary imports.

`cargo +nightly fuzz run -a -O editing` exercises bounded programs of Unicode
insertions, paragraph splits/joins, selected deletions, formatting, tracking toggles,
three authors, Accept/Reject, comments, resolution, saves and branching Undo/Redo.
An independent String model checks plain edits; saved semantic snapshots check
history; run lengths and UTF-8 boundaries are checked after each operation.
The same harness runs 128 fixed seeds (64 operations each) in the normal test suite:
`cargo test -p quill-formats --test fuzz_properties`.

Two existing behaviors are explicit in the oracle: exchange saves give each
comment one continuous first-to-last range, and resolving comments is outside
text Undo. Resolution ends the reference model's history segment; native saves
still check comment content and resolved state. This tests core editing, not
mouse hit testing, caret navigation or rendering. Those remain separate UI tests.

`character_styles` runs programs of define, apply, remove, redefine, rename,
delete, Replace Fonts, paragraph style, join, linking a paragraph style to a
character style and Undo/Redo. After every step, text must show the style it
names unless it overrides that field by hand, and a linked paragraph style must
show its character style and keep the link through a .qwp save. The same
programs run in the normal test suite. `clipboard` pastes RTF or clipboard HTML
into a document that already has conflicting style names, checks those rules,
saves, and undoes. `native` reads .qwp files and `markdown` reads Markdown,
never looking for pictures on disk. `html` and `odt` now also save and reopen,
and every target that saves checks HTML and ODT as well as native, DOCX and RTF.

Overnight campaigns also include `editing`. Failed property
checks save replayable operation programs just like parser crash inputs. Reduce
one with `cargo +nightly fuzz tmin -a -O editing <artifact>` and retain the small
program as a permanent test fixture.
